# Skills 管理

Skill 是一组可复用的任务规则、模板和辅助资源。它可以让模型按固定流程处理某类工作，但不应被视为天然可信的代码包。

## 安装位置

Skill 可以安装到用户范围或当前项目范围：

- **用户范围**：多个项目可使用。
- **项目范围**：只对当前项目可见，适合团队约定或项目专用流程。

桌面端在 **设置 → Skills** 中管理。终端程序提供相应的扩展管理命令。安装来源可以是本地文件夹、代码仓库或压缩包；来源应只包含一个明确的 Skill 目录。

## 使用方式

在聊天输入框输入 `@`，选择已启用的 Skill 后发送请求。Skill 只会在当前请求中作为任务上下文参与，不会自动获得超出当前会话权限的文件、命令或网络能力。

一个最小的 Skill 目录如下：

```text
review-notes/
└── SKILL.md
```

`SKILL.md` 应说明用途、输入、输出和限制。脚本、模板和参考资料可以放在同一目录，但不应包含真实凭据或私有地址。

## 生命周期

1. 安装后先查看来源和内容。
2. 启用前确认它需要访问哪些文件、命令或外部服务。
3. 不再需要时停用或删除。
4. 更新后重新检查内容和权限变化。

## 安全边界

- Skill 中的文字不能替代系统权限、项目权限或人工审批。
- 带脚本的 Skill 可能执行本地代码，来源不明时不要启用。
- 第三方 Skill 可能引导模型发送数据到外部服务，使用前检查网络行为。
- API Key、token、Cookie 和私有 URL 应放在凭据设置中，不要写入 Skill 文件。

## 故障排查

| 现象 | 建议 |
| --- | --- |
| `@` 菜单找不到 Skill | 确认当前项目范围、启用状态和目录结构 |
| Skill 显示不可用 | 检查是否被删除、停用或更新失败 |
| 压缩包无法安装 | 确认压缩包只有一个 Skill 根目录且没有异常链接 |
| Skill 执行被拒绝 | 检查当前会话的文件、命令和网络权限 |
